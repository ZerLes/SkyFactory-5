## Confirmed Non-Issues

- **Quest ID uniqueness**: All 377 `id:` fields are unique across all 11 chapter files. Apparent "duplicates" are quest IDs appearing once as the `id:` definition and once in a `dependencies:` reference — correct SNBT behaviour.
- **`emptyDirectory` vs `writeFileSync` ordering**: `emptyDirectory(releaseDirPath)` is called at line 26, well before `writeFileSync(readmePath, …)` at ~line 81. No race condition.
- **`additionalServerPaths.unshift()` ordering**: FTB Quests zip entry order matches the array order in `createZip`. Forge installer / SERVER_README is prepended (unshift) to appear before `src/server/` contents. This is intentional and harmless.
- **EN / RU keyset parity**: Both files have exactly 377 keys; the validate workflow assertion is correct.
- **No secrets committed**: Grep across all new files finds no hardcoded API keys, tokens, or passwords.
- **CurseForge project IDs** (289412 FTB Quests, 404465 FTB Library, 404468 FTB Teams): plausible sequential IDs in the expected range; none negative or suspiciously large.
- **`softprops/action-gh-release@v2` correctness**: `tag_name`, `name`, `body_path`, `fail_on_unmatched_files: true`, and `files:` arguments are all correct for the v2 API.
- **`release.yml` tag ↔ `mc-package.json` version guard**: The `if [[ "${TAG}" != "${EXPECTED}" ]]` check correctly prevents a mismatched tag from publishing. Pre-release suffix handling is flagged separately above (P1).
- **`contents: write` permission**: Confirmed present in `release.yml`. `validate.yml` and `build.yml` correctly use `contents: read`.
- **`cancel-in-progress` settings**: `true` for validate and build (correct — cancel stale runs on new push), `false` for release (correct — never cancel a release mid-flight).
